Chapter 18: Capstone - Building a Complete VLA Humanoid System

You've learned ROS 2 communication, digital twin simulation, NVIDIA Isaac acceleration, vision systems, and LLM-based planning. Now it's time to integrate everything into a complete humanoid robot system that can understand natural language, perceive the environment, and execute complex tasks autonomously.

The Goal: Build a humanoid robot that responds to: "Please bring me the red cup from the kitchen table"—and successfully executes this task from voice command to handover.

In this final chapter, we'll design and implement an end-to-end VLA system: from speech recognition to vision grounding to LLM planning to ROS 2 execution, deployed on a simulated humanoid in Isaac Sim and tested with real-world constraints.

Module Breakdown​

Module 1: Speech Interface​

Purpose: Convert user voice commands to text.

Technologies:

  • Whisper (OpenAI): State-of-the-art speech recognition
  • Google Cloud Speech-to-Text: Real-time streaming recognition
  • ROS 2 Package: audio_common, speech_recognition_msgs

Implementation:

import rclpy
from rclpy.node import Node
from std_msgs.msg import String
import whisper

class SpeechRecognitionNode(Node):
    def __init__(self):
        super().__init__('speech_recognition')
        self.publisher = self.create_publisher(String, '/voice_command', 10)
        self.model = whisper.load_model("base")

    def listen_and_transcribe(self, audio_file):
        """Transcribe audio to text"""
        result = self.model.transcribe(audio_file)
        command = result["text"]

        # Publish command
        msg = String()
        msg.data = command
        self.publisher.publish(msg)
        self.get_logger().info(f'Voice command: {command}')
        return command

Module 2: LLM Task Planner​

Purpose: Decompose natural language commands into action sequences.

Technologies:

  • OpenAI GPT-4 or Anthropic Claude for task planning
  • LangChain for prompt management and tool use
  • ROS 2 Service: Planner responds to planning requests

Implementation:

import rclpy
from rclpy.node import Node
from planner_msgs.srv import GeneratePlan
import openai

class LLMPlannerNode(Node):
    def __init__(self):
        super().__init__('llm_planner')
        self.service = self.create_service(
            GeneratePlan, '/generate_plan', self.plan_callback)
        openai.api_key = "YOUR_API_KEY"

    def plan_callback(self, request, response):
        """Generate action plan from user command"""
        user_command = request.command

        # Define available tools (action primitives)
        tools = [
            {
                "name": "navigate_to",
                "description": "Navigate to a location",
                "parameters": {
                    "type": "object",
                    "properties": {
                        "location": {"type": "string"}
                    },
                    "required": ["location"]
                }
            },
            {
                "name": "detect_object",
                "description": "Detect object using vision",
                "parameters": {
                    "type": "object",
                    "properties": {
                        "object_name": {"type": "string"},
                        "area": {"type": "string"}
                    },
                    "required": ["object_name"]
                }
            },
            {
                "name": "grasp",
                "description": "Grasp an object",
                "parameters": {
                    "type": "object",
                    "properties": {
                        "object": {"type": "string"}
                    },
                    "required": ["object"]
                }
            },
            {
                "name": "handover",
                "description": "Hand object to person",
                "parameters": {
                    "type": "object",
                    "properties": {
                        "object": {"type": "string"},
                        "person": {"type": "string"}
                    },
                    "required": ["object"]
                }
            }
        ]

        # Call LLM with tools
        llm_response = openai.ChatCompletion.create(
            model="gpt-4",
            messages=[
                {"role": "system", "content": "You are a humanoid robot task planner."},
                {"role": "user", "content": user_command}
            ],
            tools=tools,
            tool_choice="auto"
        )

        # Extract tool calls (action sequence)
        plan = []
        for tool_call in llm_response["choices"][0]["message"]["tool_calls"]:
            action = {
                "name": tool_call["function"]["name"],
                "parameters": json.loads(tool_call["function"]["arguments"])
            }
            plan.append(action)

        response.plan = json.dumps(plan)
        return response

Module 3: Vision System​

Purpose: Detect objects, ground language to visual entities, compute 3D positions.

Technologies:

  • Isaac ROS YOLO: Real-time object detection (30-60 FPS on GPU)
  • CLIP: Visual grounding for language queries
  • RGB-D Camera: Intel RealSense or simulated depth in Isaac Sim

Implementation (combining Chapter 16 concepts):

import rclpy
from rclpy.node import Node
from vision_msgs.msg import Detection2DArray
from geometry_msgs.msg import PointStamped
from sensor_msgs.msg import Image
import clip
import torch

class VisionGroundingNode(Node):
    def __init__(self):
        super().__init__('vision_grounding')

        # Subscribe to detections from Isaac ROS YOLO
        self.det_sub = self.create_subscription(
            Detection2DArray, '/detections', self.detections_callback, 10)

        # Subscribe to depth image
        self.depth_sub = self.create_subscription(
            Image, '/camera/depth/image_raw', self.depth_callback, 10)

        # Publisher for grounded object position
        self.pos_pub = self.create_publisher(
            PointStamped, '/grounded_object_position', 10)

        # Load CLIP
        self.device = "cuda"
        self.model, self.preprocess = clip.load("ViT-B/32", device=self.device)

        self.current_query = None  # Set by LLM planner
        self.depth_map = None

    def set_query(self, query):
        """Called by executor when LLM requests object detection"""
        self.current_query = query

    def detections_callback(self, msg):
        if not self.current_query:
            return

        # Get RGB image
        image = self.get_current_image()

        # CLIP grounding
        text = clip.tokenize([self.current_query]).to(self.device)
        text_features = self.model.encode_text(text)

        best_match = None
        best_similarity = 0.0

        for detection in msg.detections:
            bbox = detection.bbox
            crop = self.crop_image(image, bbox)
            crop_input = self.preprocess(crop).unsqueeze(0).to(self.device)
            image_features = self.model.encode_image(crop_input)

            similarity = torch.cosine_similarity(image_features, text_features).item()

            if similarity > best_similarity:
                best_similarity = similarity
                best_match = detection

        if best_match and best_similarity > 0.5:
            # Compute 3D position from depth
            position_3d = self.compute_3d_position(best_match.bbox, self.depth_map)

            # Publish
            pos_msg = PointStamped()
            pos_msg.point.x = position_3d[0]
            pos_msg.point.y = position_3d[1]
            pos_msg.point.z = position_3d[2]
            self.pos_pub.publish(pos_msg)

            self.get_logger().info(f'Grounded "{self.current_query}" at {position_3d}')

Module 4: Navigation & Manipulation​

Purpose: Execute motion plans for locomotion and arm control.

Technologies:

  • Nav2: Path planning and navigation
  • MoveIt 2: Arm motion planning for grasping
  • ROS 2 Control: Joint trajectory execution

Navigation Example:

from nav2_msgs.action import NavigateToPose
from rclpy.action import ActionClient

class NavigationExecutor:
    def __init__(self, node):
        self.nav_client = ActionClient(node, NavigateToPose, 'navigate_to_pose')

    def navigate_to(self, location_name):
        """Navigate to named location"""
        goal = NavigateToPose.Goal()
        goal.pose.header.frame_id = 'map'

        # Lookup location coordinates (from semantic map)
        location_coords = self.get_location(location_name)
        goal.pose.pose.position.x = location_coords[0]
        goal.pose.pose.position.y = location_coords[1]
        goal.pose.pose.orientation.w = 1.0

        # Send goal
        future = self.nav_client.send_goal_async(goal)
        return future

Grasping Example:

from moveit_msgs.action import Pickup
from rclpy.action import ActionClient

class ManipulationExecutor:
    def __init__(self, node):
        self.grasp_client = ActionClient(node, Pickup, 'pickup')

    def grasp(self, object_position):
        """Plan and execute grasp"""
        goal = Pickup.Goal()
        goal.target_name = "target_object"
        goal.group_name = "arm"

        # Set grasp pose from vision system
        goal.possible_grasps = self.plan_grasp(object_position)

        # Execute
        future = self.grasp_client.send_goal_async(goal)
        return future

Module 5: Execution Coordinator​

Purpose: Orchestrate all modules, execute LLM plan step-by-step, handle failures.

Implementation:

import rclpy
from rclpy.node import Node
import json

class ExecutionCoordinator(Node):
    def __init__(self):
        super().__init__('execution_coordinator')

        # Clients for all subsystems
        self.planner = LLMPlannerNode()
        self.vision = VisionGroundingNode()
        self.navigation = NavigationExecutor(self)
        self.manipulation = ManipulationExecutor(self)

    def execute_command(self, voice_command):
        """Execute voice command end-to-end"""
        self.get_logger().info(f'Executing: {voice_command}')

        # Step 1: Generate plan from LLM
        plan = self.generate_plan(voice_command)
        self.get_logger().info(f'Plan: {plan}')

        # Step 2: Execute plan step-by-step
        for action in plan:
            result = self.execute_action(action)

            if result == "FAILURE":
                # Replan
                self.get_logger().warn(f'Action failed: {action}. Replanning...')
                plan = self.replan(voice_command, action)
                continue

        self.get_logger().info('Task completed successfully')

    def execute_action(self, action):
        """Execute single action primitive"""
        action_name = action["name"]
        params = action["parameters"]

        if action_name == "navigate_to":
            return self.navigation.navigate_to(params["location"])

        elif action_name == "detect_object":
            self.vision.set_query(params["object_name"])
            # Wait for vision system to ground object
            position = self.wait_for_grounding()
            return "SUCCESS" if position else "FAILURE"

        elif action_name == "grasp":
            object_position = self.get_last_grounded_position()
            return self.manipulation.grasp(object_position)

        elif action_name == "handover":
            return self.execute_handover(params["object"])

    def execute_handover(self, object_name):
        """Hand object to human"""
        # Navigate close to human
        self.navigation.navigate_to("user")

        # Extend arm
        self.manipulation.extend_arm_for_handover()

        # Wait for force sensor release (human took object)
        self.wait_for_handover_complete()

        # Confirm verbally
        self.speak("I've brought you the " + object_name)
        return "SUCCESS"

Testing and Validation​

Test Scenarios​

  1. Nominal Case: "Bring me the red cup"

    • All components work as designed
    • Expected: Success in 20-30 seconds

  2. Occlusion: Red cup is behind laptop

    • Vision detects occlusion
    • LLM replans to move laptop first

  3. Ambiguity: Two red cups on table

    • Robot asks: "Which red cup? The one on the left or right?"

  4. Obstacle: Path to kitchen is blocked

    • Nav2 detects obstacle
    • Replans path around obstacle

  5. Grasp Failure: Cup slips during grasp

    • Force sensor detects failure
    • LLM replans: retry grasp with adjusted grip

Validation Metrics​

Functional Metrics:

  • Success Rate: Percentage of tasks completed successfully (target: greater than 80%)
  • Execution Time: Time from command to completion (target: less than 60 seconds)
  • Failure Recovery: Percentage of failures successfully recovered via replanning (target: greater than 60%)

Performance Metrics:

  • Vision Latency: Object detection + grounding (target: less than 200ms)
  • LLM Planning Latency: Plan generation time (target: less than 2 seconds)
  • Navigation Speed: Average walking speed (target: 0.5-1.0 m/s)

Safety Metrics:

  • Collision Rate: Collisions per 100 tasks (target: 0)
  • Grasp Success Rate: Successful grasps without dropping (target: greater than 90%)

Deployment: From Simulation to Physical Robot​

Sim-to-Real Transfer Checklist​

  1. Domain Randomization in Isaac Sim:

    • Vary object positions, lighting, floor friction
    • Add sensor noise (camera, IMU, joint encoders)
    • Randomize robot mass distribution (±10%)

  2. Hardware Selection:

    • Compute: NVIDIA Jetson AGX Orin (64GB)
    • Sensors: Intel RealSense D435i (RGB-D camera)
    • Actuators: High-torque servo motors (Dynamixel or similar)
    • IMU: 6-axis for balance

  3. Software Optimization:

    • Convert vision models to TensorRT (FP16 for speed)
    • Run LLM planning on cloud (low-latency 5G connection) or edge (smaller models)
    • Use Nav2 optimized parameters for physical robot dynamics

  4. Calibration:

    • Camera intrinsics calibration (focal length, principal point)
    • Hand-eye calibration (camera pose relative to robot base)
    • Joint calibration (encoder offsets, gear ratios)

  5. Testing:

    • Start with simple tasks (navigate, detect objects)
    • Gradually increase complexity (grasp, handover)
    • Collect failure data → fine-tune models

Advanced Extensions​

1. Multi-Step Dialogue​

User: "Bring me a cup" Robot: "Which cup? The red one or the blue one?" User: "The red one" Robot: Executes task

Implementation: Maintain conversation history in LLM context, use clarification questions as action primitive.

2. Learning from Demonstration​

User: Teleoperates robot to demonstrate task Robot: Records state-action trajectory Robot: Learns policy via imitation learning (behavior cloning)

Use Case: Teach robot novel tasks (folding towels, pouring liquids).

3. Multi-Robot Coordination​

Scenario: Two humanoids set the table together

  • LLM decomposes task into subtasks
  • Allocates subtasks to robots (Robot A: plates, Robot B: utensils)
  • Robots coordinate to avoid collisions

4. Long-Horizon Tasks​

Task: "Prepare the living room for guests"

  • Tidy clutter (10 objects)
  • Vacuum floor (if robot has attachment)
  • Set out drinks and snacks

Challenge: 50+ action sequence, multiple failure points Solution: Hierarchical planning (LLM generates high-level plan, low-level planner fills details).

Lessons Learned and Best Practices​

1. Modularity is Key​

Principle: Each subsystem (speech, vision, planning, navigation) should be independent ROS 2 node.

Benefit: Easy to test, debug, and upgrade individual components.

2. Graceful Degradation​

Principle: If a component fails (e.g., vision system crashes), system should degrade gracefully.

Example:

  • Vision fails → Use last known object positions
  • LLM timeout → Use cached plan for common task

3. Logging and Debugging​

Principle: Log all sensor data, action commands, LLM prompts/responses.

Benefit: Replay failed tasks, analyze root causes, improve models.

4. Sim-to-Real Gap​

Principle: Simulation is never perfect; expect less than 100% transfer.

Mitigation:

  • Domain randomization during training
  • Fine-tuning on real robot data (100-500 examples)
  • Iterative improvement based on failure analysis

  1. Speech Interface: Voice command → text (Whisper)

Advanced Extensions:

Best Practices:

  • Modularity (independent ROS 2 nodes)
  • Graceful degradation (fallback strategies)
