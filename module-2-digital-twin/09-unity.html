Chapter 9: Unity for Perception and Interaction

Your humanoid robot's object detection system works flawlessly in Gazebo—detecting simple geometric shapes with 95% accuracy. But when you deploy it on the physical robot in a cluttered living room with varied lighting, performance plummets to 60%. The problem? Your AI model was trained on unrealistic, oversimplified visual data.

Enter Unity: a game engine that renders photorealistic environments with complex lighting, textures, and shadows. By training perception models in Unity's high-fidelity simulations, you can generate diverse visual data that generalizes to the real world. Unity complements Gazebo perfectly—while Gazebo excels at physics and control, Unity specializes in perception, rendering, and human-robot interaction (HRI).

In this chapter, we'll explore Unity's role in humanoid robotics: synthetic data generation, perception training, HRI simulation, and its integration with ROS 2.

What is Unity?​

Unity is a real-time 3D development platform originally designed for video games, now widely used in robotics, autonomous vehicles, and industrial simulation. Unity's strengths are:

  1. Photorealistic Rendering: Advanced graphics pipelines (HDRP - High Definition Render Pipeline) produce realistic lighting, shadows, reflections, and materials.
  2. Cross-Platform: Deploy to Windows, Linux, macOS, mobile, VR/AR headsets, and web browsers.
  3. Asset Ecosystem: Massive library of 3D models, environments, and tools (Unity Asset Store).
  4. ML Integration: Unity ML-Agents toolkit for reinforcement learning and imitation learning.

When to Use Unity:

  • Training computer vision models (object detection, semantic segmentation).
  • Simulating human-robot interaction scenarios.
  • Generating synthetic training data with domain randomization.
  • Creating VR interfaces for robot teleoperation.

When NOT to Use Unity:

  • Precise contact dynamics (e.g., bipedal walking, grasping)—use Gazebo or NVIDIA Isaac Sim instead.
  • Real-time control loops requiring < 1 ms latency.

Unity for Humanoid Robotics: Key Use Cases​

1. Synthetic Data Generation for Perception​

Training robust perception models requires thousands of annotated images: bounding boxes for object detection, pixel masks for segmentation, 3D poses for manipulation. Manually labeling real-world data is expensive and time-consuming.

Unity's Solution: Automatically generate labeled data.

Example: Object Detection Training​

Scenario: Train a humanoid to detect "cup", "book", "bottle" in home environments.

Unity Workflow:

  1. Create environments: Living rooms with furniture, lighting variations, clutter.
  2. Place objects: Randomize positions, orientations, scales of cups, books, bottles.
  3. Render images: Capture RGB images from robot's camera viewpoint.
  4. Export labels: Automatically generate bounding boxes (YOLO format), pixel masks (COCO format).

Domain Randomization: Vary lighting (daylight, indoor lamps, shadows), textures (wood, plastic, metal), backgrounds (clean vs. cluttered) to prevent overfitting to specific conditions.

Result: 10,000 labeled images generated in hours (vs. weeks of manual labeling), improving model generalization to real-world environments.

2. Human-Robot Interaction (HRI) Simulation​

Testing HRI scenarios on physical robots is slow and requires human participants. Unity enables rapid prototyping of interaction scenarios.

Example: Handover Task​

Scenario: Humanoid hands a water bottle to a human.

Unity Workflow:

  1. Simulate human avatar: Animated character walks to robot, extends hand.
  2. Robot control: ROS 2 nodes command robot arm to grasp bottle and extend toward human.
  3. Perception: Robot's camera detects human hand position using pose estimation.
  4. Handover: Transfer object when contact is detected.

Benefits:

  • Test edge cases: What if human is too far? Too close? Moving?
  • Validate gesture recognition (waving, pointing).
  • Measure reaction times without human safety concerns.

3. VR Teleoperation Interfaces​

Unity supports VR headsets (Meta Quest, HTC Vive), enabling immersive robot control.

Example: Remote Humanoid Control​

Scenario: Operator wears VR headset to control humanoid remotely.

Unity Workflow:

  1. Live feed: Stream robot's camera views to VR headset.
  2. Motion mapping: Operator's hand movements (tracked by VR controllers) map to robot arm commands.
  3. Visual feedback: Display robot joint states, sensor data in VR overlay.

Applications:

  • Disaster response (control humanoid in hazardous environments from safe location).
  • Medical robotics (surgeon controls surgical robot with VR interface).
  • Research (collect human demonstrations for imitation learning).

4. Reinforcement Learning Training​

Unity ML-Agents toolkit enables training policies via reinforcement learning (RL).

Example: Bipedal Locomotion via RL​

Challenge: Learning to walk through trial-and-error requires thousands of episodes. Physical robots can't crash thousands of times.

Unity Solution:

  1. Parallel environments: Run 100+ humanoid simulations in parallel.
  2. Reward function: Penalize falls, reward forward progress and energy efficiency.
  3. Training: RL algorithm (PPO, SAC) learns walking policy over millions of steps.
  4. Transfer: Deploy trained policy to Gazebo (more accurate physics) for validation.

Domain Randomization: Vary friction, mass distribution, joint stiffness to improve real-world transfer.

Unity + ROS 2 Integration​

Unity doesn't natively support ROS 2, but ROS-TCP-Connector bridges the gap.

Architecture​

Unity Simulation
   ↓
ROS-TCP-Endpoint (Unity plugin)
   ↓
TCP/IP Connection
   ↓
ROS-TCP-Connector (ROS 2 node)
   ↓
ROS 2 Topics/Services/Actions
   ↓
Robot Control Code

Example: Sending Joint Commands from ROS 2 to Unity​

ROS 2 Node (Python):

# Publish joint position command
joint_msg = JointState()
joint_msg.name = ['shoulder_pitch', 'elbow_roll']
joint_msg.position = [0.5, 1.2]
joint_pub.publish(joint_msg)

Unity Receiver (C#):

// Receive joint command and update robot model
ROSConnection.GetOrCreateInstance().Subscribe<JointStateMsg>("joint_commands", UpdateJoints);

void UpdateJoints(JointStateMsg msg) {
    for (int i = 0; i < msg.name.Length; i++) {
        ArticulationBody joint = FindJoint(msg.name[i]);
        joint.xDrive = new ArticulationDrive { target = msg.position[i] * Mathf.Rad2Deg };
    }
}

Bidirectional: Unity can also publish sensor data (camera images, IMU) back to ROS 2 topics.

Unity for Perception: A Complete Example​

Let's walk through training an object detector for humanoid grasping.

Step 1: Create Scene​

Build a living room environment in Unity:

  • Furniture (couch, table, shelf).
  • Objects to detect (cups, books, remote controls).
  • Lighting (windows with sunlight, lamps).

Step 2: Set Up Perception Camera​

Attach Perception Package (Unity's computer vision tool) to robot's camera:

  • Define labels: "cup", "book", "remote".
  • Configure annotations: Bounding boxes, semantic segmentation masks.

Step 3: Randomize Environment​

Use Unity's Randomizers:

  • Object placement: Random positions on table/shelf.
  • Lighting: Vary time of day, lamp intensity.
  • Textures: Swap furniture materials (leather vs. fabric).
  • Background clutter: Add/remove decorative items.

Step 4: Generate Dataset​

Run simulation for 10,000 iterations:

  • Each iteration: Randomize scene, capture image, export labels.
  • Output: 10,000 RGB images + COCO-format annotations.

Step 5: Train Model​

Use exported data to train YOLOv8 or Faster R-CNN object detector:

python train.py --data unity_dataset --model yolov8 --epochs 100

Step 6: Deploy and Test​

  1. Test in Gazebo: Load trained model, test detection accuracy in Gazebo simulation.
  2. Transfer to Real Robot: Deploy model on physical humanoid, evaluate performance.

Expected Result: Model trained on Unity data generalizes well to real world due to diverse, realistic training images.

Gazebo vs. Unity: Which to Use?​

Many projects use both:

  • Develop perception models in Unity (synthetic data).
  • Test control algorithms in Gazebo (physics validation).
  • Deploy on real hardware (final validation).

Limitations of Unity for Robotics​

  1. Physics Accuracy: PhysX (Unity's physics engine) is optimized for games, not robotics. Contact dynamics are less accurate than Gazebo's engines.
  2. ROS Integration Complexity: Requires custom plugins (ROS-TCP-Connector), not as seamless as Gazebo's native support.
  3. Robotics Tooling: Fewer robotics-specific tools (no native URDF import, limited sensor models).
  4. Learning Curve: Unity is a general-purpose game engine; robotics workflows require custom setup.

Best Practice: Use Unity for its strengths (perception, rendering) and offload physics-critical tasks to Gazebo or NVIDIA Isaac Sim.

Unity ML-Agents: Reinforcement Learning for Humanoids​

Unity ML-Agents is a toolkit for training RL agents in Unity environments.

Key Features​

  • Parallel Training: Run hundreds of agents simultaneously.
  • Customizable Rewards: Define reward functions for specific tasks.
  • Integration with PyTorch/TensorFlow: Train using standard RL libraries.
  • Curriculum Learning: Gradually increase task difficulty.

Example: Teaching Humanoid to Stand​

Setup:

  • Humanoid starts in random poses.
  • Reward: +1 for upright torso, -0.1 per timestep, -10 for falling.
  • Observation: Joint positions, velocities, IMU data.
  • Action: Joint torques.

Training: After 1 million steps (1-2 hours on GPU), humanoid learns to stand from any initial pose.

Transfer: Trained policy can be exported to ONNX format and run on real robot via ONNX Runtime.

Summary​

Unity is a powerful complement to Gazebo for humanoid robotics development. While Gazebo excels at physics-based testing, Unity shines in:

  • Photorealistic rendering for perception training.
  • Synthetic data generation with domain randomization.
  • Human-robot interaction simulation with realistic environments.
  • VR/AR interfaces for teleoperation and visualization.

By combining Unity's visual fidelity with ROS 2 integration (via ROS-TCP-Connector), developers can train robust perception systems, prototype HRI scenarios, and accelerate AI model development. When used alongside Gazebo, Unity completes the simulation toolkit for humanoid robotics—covering perception, control, and interaction.
