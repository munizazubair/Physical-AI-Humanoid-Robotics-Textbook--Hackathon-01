# Chapter 17: LLM-Based Action Planning for Humanoids

You tell your humanoid robot: **"Set the table for dinner."** The robot must decompose this high-level goal into a sequence of actions: fetch plates from the cabinet, place them on the table, fetch utensils, arrange them properly, fetch glasses, and so on. Traditional robotics would require hard-coding every step. With **Large Language Models (LLMs)**, the robot can **reason** about the task and generate a plan autonomously.

LLMs like GPT-4, Claude, and PaLM are transforming robotics by enabling robots to:
- **Understand natural language goals**: "Set the table" → implicit sequence of subtasks
- **Decompose complex tasks**: High-level goals → step-by-step action plans
- **Reason about constraints**: "Don't stack fragile items" → adjust plan
- **Adapt to feedback**: "Actually, we need 4 plates, not 3" → replan

In this chapter, we'll explore how LLMs enable action planning for VLA systems: how they translate language to robot actions, how to ground LLM outputs in executable code (via action primitives and tool use), and how to handle errors and replanning.

---

## Why LLMs for Action Planning?

### Traditional Approach: Hardcoded Plans

**Command**: "Set the table"

**Traditional System**:
```python
def set_table():
    navigate_to(cabinet)
    open(cabinet_door)
    grasp(plate)
    navigate_to(table)
    place(plate, position=(0.3, 0.2, 0.8))
    # Repeat for each item...
```

**Limitations**:
- Fixed sequence: Cannot adapt to "set the table for 4 people" vs. "for 2 people"
- No reasoning: Cannot handle "the cabinet is locked"
- No generalization: Need separate function for "set_table", "clear_table", "serve_drinks"

---

### LLM Approach: Reasoning and Planning

**Command**: "Set the table for 4 people"

**LLM Reasoning**:
```
Task: Set table for 4 people
Required items: 4 plates, 4 forks, 4 knives, 4 glasses
Locations: plates in cabinet, utensils in drawer, glasses in upper cabinet
Plan:
1. Fetch 4 plates from cabinet → place on table
2. Fetch 4 forks from drawer → place next to plates
3. Fetch 4 knives from drawer → place next to forks
4. Fetch 4 glasses from upper cabinet → place above plates
```

**Advantages**:
- **Adaptive**: Adjust plan based on number of people
- **Reasoning**: Infers required items from goal
- **Generalizable**: Same LLM handles "set table", "clear table", "prepare breakfast"

## LLM Action Planning Pipeline

Let's trace how an LLM translates **"Bring me the book on the table"** into executable robot actions.

### Step 1: Natural Language Input

**User**: "Bring me the book on the table"

---

### Step 2: LLM Task Decomposition

**LLM Prompt**:
```
You are a humanoid robot assistant. Your task is to plan actions for the following command:

Command: "Bring me the book on the table"

Available action primitives:
- navigate_to(location): Move to a location
- detect_object(object_name, location): Use vision to find object
- grasp(object): Pick up object
- handover(object, person): Hand object to person

Output a step-by-step plan as a Python list of actions.
```

**LLM Output**:
```python
plan = [
    "detect_object('book', 'table')",  # Find book on table
    "navigate_to('table')",             # Walk to table
    "grasp('book')",                    # Pick up book
    "navigate_to('human')",             # Walk to human
    "handover('book', 'human')"         # Hand book to human
]
```

---

### Step 3: Action Grounding

Translate LLM output (Python strings) to ROS 2 action calls.

**Action Executor**:
```python
import rclpy
from rclpy.action import ActionClient
from nav2_msgs.action import NavigateToPose
from manipulation_msgs.action import Grasp

class ActionExecutor:
    def __init__(self):
        self.nav_client = ActionClient(self, NavigateToPose, 'navigate_to_pose')
        self.grasp_client = ActionClient(self, Grasp, 'grasp')

    def execute_plan(self, plan):
        for action_str in plan:
            # Parse action string
            action_name, args = self.parse_action(action_str)

            # Execute action
            if action_name == "navigate_to":
                location = args[0]
                self.execute_navigation(location)
            elif action_name == "grasp":
                object_name = args[0]
                self.execute_grasp(object_name)
            elif action_name == "handover":
                object_name, person = args
                self.execute_handover(object_name, person)

    def execute_navigation(self, location):
        goal = NavigateToPose.Goal()
        goal.pose = self.get_location_pose(location)  # Lookup location coordinates
        self.nav_client.send_goal_async(goal)
        # Wait for completion...
```

---

### Step 4: Execution with Feedback

Robot executes plan step-by-step. If any action fails, report back to LLM for replanning.

**Failure Example**:
```
Executing: navigate_to('table')
Result: SUCCESS

Executing: grasp('book')
Result: FAILURE - Object not detected (book is under laptop)
```

**Replanning Request to LLM**:
```
The grasp action failed because the book is under the laptop. Please provide an updated plan.

Available actions:
- move_object(object1, new_location): Move one object to make space
- All previous actions

Original plan:
[navigate_to('table'), grasp('book'), navigate_to('human'), handover('book', 'human')]

Failed at: grasp('book') - book is under laptop
```

**LLM Replanning**:
```python
updated_plan = [
    "move_object('laptop', 'table_edge')",  # Move laptop aside
    "grasp('book')",                         # Now grasp book
    "move_object('laptop', 'table_center')", # Put laptop back
    "navigate_to('human')",
    "handover('book', 'human')"
]
```

## Action Primitives: The LLM-Robot Interface

LLMs cannot directly control robot joints or motors. Instead, we define **action primitives**—high-level reusable actions that LLM can compose.

### Common Action Primitives for Humanoids

| Primitive | Description | Parameters | ROS 2 Action |
|-----------|-------------|------------|--------------|
| `navigate_to(location)` | Move to location | location name or coordinates | Nav2 `NavigateToPose` |
| `grasp(object)` | Pick up object | object name | MoveIt 2 `Pickup` |
| `place(object, location)` | Put object at location | object, location | MoveIt 2 `Place` |
| `handover(object, person)` | Hand object to person | object, person ID | Custom action |
| `detect_object(object, area)` | Find object in area | object name, search area | Vision service call |
| `open(container)` | Open door/drawer | container name | Manipulation action |
| `close(container)` | Close door/drawer | container name | Manipulation action |
| `move_object(object, location)` | Move object | object, new location | Combined grasp + place |
| `pour(source, dest)` | Pour liquid | source container, destination | Complex manipulation |
| `push(object, direction)` | Push object | object, direction | Contact manipulation |

---

### Defining Action Primitives in Code

```python
class ActionPrimitives:
    def __init__(self, ros_node):
        self.node = ros_node
        self.nav_client = ActionClient(ros_node, NavigateToPose, 'navigate_to_pose')
        self.grasp_client = ActionClient(ros_node, Grasp, 'grasp')
        self.place_client = ActionClient(ros_node, Place, 'place')

    def navigate_to(self, location):
        """Navigate to a named location or coordinates"""
        goal = NavigateToPose.Goal()
        goal.pose = self.resolve_location(location)
        future = self.nav_client.send_goal_async(goal)
        rclpy.spin_until_future_complete(self.node, future)
        return future.result().status  # SUCCESS or FAILURE

    def grasp(self, object_name):
        """Grasp object by name (uses vision to locate)"""
        # Use vision system to get object pose
        object_pose = self.detect_object(object_name)
        if not object_pose:
            return "FAILURE - Object not found"

        # Plan grasp with MoveIt 2
        goal = Grasp.Goal()
        goal.target_pose = object_pose
        future = self.grasp_client.send_goal_async(goal)
        rclpy.spin_until_future_complete(self.node, future)
        return future.result().status

    def place(self, object_name, location):
        """Place held object at location"""
        goal = Place.Goal()
        goal.target_pose = self.resolve_location(location)
        future = self.place_client.send_goal_async(goal)
        rclpy.spin_until_future_complete(self.node, future)
        return future.result().status

    def handover(self, object_name, person):
        """Extend arm toward person for handover"""
        # Detect person location
        person_pose = self.detect_person(person)
        # Navigate close to person
        self.navigate_to(person_pose, distance=0.5)  # Stand 0.5m away
        # Extend arm at chest height
        self.move_arm_to_pose(person_pose + offset(0, 0, 1.2))  # Chest height
        # Wait for person to take object (detect force sensor release)
        self.wait_for_handover_complete()
        return "SUCCESS"

    def detect_object(self, object_name, area="workspace"):
        """Use vision system to locate object"""
        # Call vision service (Chapter 16)
        request = DetectObject.Request()
        request.object_name = object_name
        request.search_area = area
        response = self.vision_client.call(request)
        return response.pose if response.success else None
```

## LLM Prompting for Robot Planning

### Prompt Design

**Key Elements**:
1. **Role**: Define robot's capabilities and constraints
2. **Action primitives**: List available actions with signatures
3. **Task**: User command
4. **Output format**: Specify desired format (Python list, JSON, etc.)
5. **Constraints**: Safety rules, object properties

**Example Prompt Template**:
```
You are a humanoid robot assistant capable of navigation, manipulation, and object perception.

Available action primitives:
- navigate_to(location: str) -> None: Move to a location
- grasp(object: str) -> None: Pick up an object
- place(object: str, location: str) -> None: Place object at location
- detect_object(object: str, area: str) -> Pose: Find object in area
- handover(object: str, person: str) -> None: Hand object to person

Current environment:
- Locations: kitchen, living_room, table, cabinet, drawer
- Objects detected: book (on table), cup (on table), laptop (on table)
- People: user (in living_room)

Task: "{user_command}"

Constraints:
- Always detect object location before grasping
- Do not grasp multiple objects simultaneously
- Navigate to object before grasping
- Check for obstacles before navigation

Output a Python list of action calls:
```

**LLM Response**:
```python
[
    "detect_object('book', 'table')",
    "navigate_to('table')",
    "grasp('book')",
    "navigate_to('living_room')",
    "handover('book', 'user')"
]
```


## Handling Uncertainty and Failures

### Error Types

1. **Action Failure**: Grasp failed (object slipped)
2. **Precondition Violation**: Cannot grasp (object is too heavy)
3. **Environment Change**: Object moved while robot was navigating
4. **Safety Violation**: Collision detected during navigation

---

### Replanning with LLM

When an action fails, send feedback to LLM for replanning.

**Feedback Template**:
```
Execution failed at step {step_index}:
Action: {failed_action}
Reason: {failure_reason}
Current state: {current_state}

Original plan:
{original_plan}

Please provide an updated plan to achieve the goal.
```

**Example**:
```
Execution failed at step 2:
Action: grasp('book')
Reason: Object is underneath another object (laptop)
Current state: Robot is at table, book detected under laptop

Original plan:
["navigate_to('table')", "grasp('book')", "navigate_to('user')", "handover('book', 'user')"]

Please provide an updated plan.
```

**LLM Replanning**:
```python
updated_plan = [
    "grasp('laptop')",                # Move obstacle
    "place('laptop', 'table_side')",  # Set aside
    "grasp('book')",                  # Now grasp book
    "grasp('laptop')",                # Restore original state
    "place('laptop', 'table_center')",
    "navigate_to('user')",
    "handover('book', 'user')"
]
```

---

### Iterative Execution Loop

```python
def execute_with_replanning(user_command, max_retries=3):
    plan = llm_generate_plan(user_command)

    for attempt in range(max_retries):
        for step_index, action in enumerate(plan):
            result = execute_action(action)

            if result == "FAILURE":
                # Request replanning
                feedback = f"Action '{action}' failed at step {step_index}"
                plan = llm_replan(user_command, plan, step_index, feedback)
                break  # Restart with new plan

            elif result == "SUCCESS":
                continue  # Next action

        else:
            # All actions succeeded
            return "Task completed successfully"

    return "Task failed after max retries"
```

## Advanced LLM Planning: Tool Use

Modern LLMs (GPT-4, Claude, PaLM) support **tool use** (function calling)—LLM can invoke functions directly instead of generating code strings.

### Tool Use API (OpenAI Function Calling)

**Define Tools**:
```python
tools = [
    {
        "name": "navigate_to",
        "description": "Navigate robot to a location",
        "parameters": {
            "type": "object",
            "properties": {
                "location": {"type": "string", "description": "Target location name"}
            },
            "required": ["location"]
        }
    },
    {
        "name": "grasp",
        "description": "Grasp an object",
        "parameters": {
            "type": "object",
            "properties": {
                "object": {"type": "string", "description": "Object to grasp"}
            },
            "required": ["object"]
        }
    },
    # Define all action primitives...
]
```

**LLM Request**:
```python
import openai

response = openai.ChatCompletion.create(
    model="gpt-4",
    messages=[
        {"role": "system", "content": "You are a humanoid robot planner."},
        {"role": "user", "content": "Bring me the book on the table"}
    ],
    tools=tools,
    tool_choice="auto"  # LLM decides when to call tools
)

# LLM outputs tool calls
tool_calls = response["choices"][0]["message"]["tool_calls"]

for tool_call in tool_calls:
    function_name = tool_call["function"]["name"]
    arguments = json.loads(tool_call["function"]["arguments"])
    execute_action(function_name, **arguments)
```

**LLM Response** (tool calls):
```json
[
    {"function": "navigate_to", "arguments": {"location": "table"}},
    {"function": "grasp", "arguments": {"object": "book"}},
    {"function": "navigate_to", "arguments": {"location": "user"}},
    {"function": "handover", "arguments": {"object": "book", "person": "user"}}
]
```

**Advantages**:
- Structured output (JSON, not Python strings)
- Type safety (LLM follows parameter schemas)
- Easier to parse and execute

## Multi-Step Reasoning with LLMs

For complex tasks, LLMs can reason step-by-step before generating plans.

### Chain-of-Thought Prompting

**Prompt**:
```
Task: "Prepare breakfast for 2 people"

Think step-by-step about what needs to be done, then output the action plan.
```

**LLM Reasoning (Chain-of-Thought)**:
```
Thought: Breakfast for 2 people typically includes plates, utensils, food, and drinks.
Step 1: Set the table (2 plates, 2 forks, 2 knives)
Step 2: Prepare food (toast, eggs - but robot may not cook; fetch pre-made items)
Step 3: Serve drinks (pour juice or coffee)

Action plan:
[
    "navigate_to('cabinet')",
    "grasp('plate')",
    "navigate_to('table')",
    "place('plate', 'table_position_1')",
    "navigate_to('cabinet')",
    "grasp('plate')",
    "navigate_to('table')",
    "place('plate', 'table_position_2')",
    # ... (repeat for utensils)
    "navigate_to('fridge')",
    "open('fridge')",
    "grasp('juice')",
    "navigate_to('table')",
    "pour('juice', 'glass_1')",
    "pour('juice', 'glass_2')"
]
```

**Benefit**: Explicit reasoning improves plan quality for complex tasks.

## Safety and Constraints

LLMs can generate unsafe or infeasible plans. We must enforce constraints.

### Safety Constraints

**Hard Constraints** (enforced by executor):
- Do not grasp heavy objects (over 5 kg weight limit)
- Do not navigate near stairs without handrails
- Do not place fragile objects on unstable surfaces
- Do not move person's personal items without permission

**Soft Constraints** (guide LLM via prompt):
- Prefer shorter paths
- Minimize energy use
- Avoid cluttered areas

---

### Constraint Enforcement

**Pre-Execution Validation**:
```python
def validate_action(action):
    if action.type == "grasp":
        object_weight = get_object_weight(action.object)
        if object_weight > 5.0:  # kg
            return "INVALID - Object too heavy"

    if action.type == "navigate_to":
        if is_hazardous(action.location):
            return "INVALID - Hazardous area"

    return "VALID"
```

**LLM Prompt with Constraints**:
```
Constraints:
- Do not grasp objects heavier than 5 kg
- Do not navigate to hazardous areas (stairs, pool)
- Always confirm before moving personal items

Task: "Move the laptop to the desk"
```

**LLM Output**:
```python
[
    "ask_permission('May I move your laptop?')",  # Respect constraint
    "wait_for_confirmation()",
    "grasp('laptop')",
    "navigate_to('desk')",
    "place('laptop', 'desk')"
]
```

## Challenges and Limitations

### 1. LLM Hallucination

**Problem**: LLM generates actions that don't exist or misunderstands constraints.

**Example**:
```python
["fly_to('ceiling')"]  # Robot cannot fly!
```

**Mitigation**:
- Strict action primitive whitelist (reject undefined actions)
- Validation before execution
- Few-shot examples that demonstrate valid actions

---

### 2. Grounding Errors

**Problem**: LLM uses object names that don't match detected objects.

**Example**:
- LLM: `grasp('mug')`
- Vision system detected: `cup` (not `mug`)

**Mitigation**:
- Semantic matching (mug ≈ cup)
- Provide LLM with current object detections in prompt

---

### 3. Long Plans

**Problem**: LLM generates 50-step plan; any failure requires full replan.

**Mitigation**:
- Hierarchical planning: LLM generates high-level plan, low-level planner fills details
- Incremental execution: Execute 3-5 steps, then ask LLM for next steps

---

### 4. Latency

**Problem**: LLM inference takes 500ms-2s; too slow for real-time control.

**Mitigation**:
- LLM plans high-level (slow), executor handles low-level reactive control (fast)
- Cache plans for common tasks ("set table" template stored, LLM adjusts parameters)

## Summary

**LLMs enable humanoid robots to understand high-level goals and autonomously generate action plans.** Key capabilities:

1. **Task Decomposition**: "Set the table" → Fetch plates, utensils, glasses
2. **Action Primitives**: LLMs compose reusable building blocks (navigate, grasp, place)
3. **Reasoning**: Handle constraints, adapt to failures, replan dynamically
4. **Tool Use**: Modern LLMs call functions directly (structured output)
5. **Multi-Step Reasoning**: Chain-of-thought improves complex task planning

**LLM Planning Pipeline**:
1. User command → LLM prompt
2. LLM generates plan (list of action primitives)
3. Executor translates actions → ROS 2 calls
4. Execute step-by-step
5. On failure → Send feedback to LLM → Replan

**Action Primitives for Humanoids**:
- `navigate_to(location)`: Move to location
- `grasp(object)`: Pick up object
- `place(object, location)`: Put object down
- `handover(object, person)`: Hand object to human
- `detect_object(object, area)`: Use vision to locate object
- `open/close(container)`: Manipulate doors/drawers

**Challenges**:
- LLM hallucination (invalid actions)
- Grounding errors (mismatched object names)
- Long plans (failure recovery expensive)
- Latency (LLM inference is slow)

**Safety**:
- Hard constraints enforced by executor (weight limits, hazard avoidance)
- Soft constraints in LLM prompt (energy efficiency, clutter avoidance)
- Pre-execution validation (reject unsafe actions)

**Advanced Techniques**:
- **Tool use** (function calling): Structured output, type-safe parameters
- **Chain-of-thought**: Explicit reasoning for complex tasks
- **Few-shot prompting**: Examples improve plan quality
- **Iterative execution**: Replan on failures (up to max retries)
